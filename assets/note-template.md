# 具体指南

- 核心笔记文件固定命名为 `设计思路与证据审查.md`。
- Obsidian 笔记属性采用 YAML Frontmatter，必须位于 Markdown 文件最开头。第一条 `---` 之前不能有空行、标题或说明文字。
- 两条 `---` 之间是 Obsidian 笔记属性，不属于正文，也没有 Markdown 文字级别；不得在属性字段前添加 `#`、`##` 或 `###`。
- 第二条 `---` 结束后空一行，直接进入正文的第一个内容部分，不再重复书写论文中文题目。
- `title`填写准确的论文中文题目；`title_en`填写论文英文原题。中文题目只在笔记属性中出现一次，不再设置单独的正文一级标题。
- `first_authors`填写第一作者及全部共同第一作者；`authors`填写一般作者；`corresponding_authors`填写全部通讯作者。作者之间使用中文分号 `；`。
- 中国作者优先使用经可靠来源核实的中文姓名；无法核实具体汉字时保留论文中的英文拼写，不得根据拼音猜测。外国作者保留原始姓名。
- `affiliations`填写论文列出的全部作者单位，按照论文编号顺序排列，全部翻译成中文并用中文分号分隔；不得省略、合并或只写第一单位。
- `journal`填写期刊官方全称；有与全称不同的公认缩写时，写为“官方全称；通用缩写”。若缩写与全称完全相同，只写一次，不得出现 `Science；Science` 这类重复值。
- `year`、`volume`和`issue`按正式发表信息填写；不存在或无法确认时写 `null`。
- `pages`只填写传统连续页码；没有连续页码时写 `""`，不得填入文章号、eLocator或DOI尾号。
- `doi`只填写DOI本体，不添加网址或 `doi:` 前缀；没有时写 `""`。
- `published`使用正式发表日期，格式为 `YYYY-MM-DD`；无法确认具体日期时写 `null`。
- `tags`保持单行，只填写3至6个与论文直接相关的疾病、表型、对象、机制、材料、通路、细胞或器官主题；不得加入“文献精读”“实验设计”“证据审查”等笔记管理标签。
- 字段名称、顺序和数据格式固定。所有信息必须回查论文首页、作者说明、期刊正式页面和DOI信息；不得猜测、编造或在成稿中保留占位符。

# 全文执行优先级｜深度、逻辑与完整度高于格式

> [!danger] 最高优先级原则
> 这份模板的根本目标是产生一份足够深、逻辑闭合、证据覆盖完整的文献精读笔记，而不是产生一份形式整齐的填空文档。当具体标题、Callout、顺序、表达方式或示例占位与论文的真实论证结构发生矛盾时，应当优先保全分析深度、证据逻辑和内容完整度，可以不遵循该处具体格式。

## 深度要求

- 不得停留在摘要复述、Figure翻译或“做了什么—得到什么”的表层总结。要追问作者为什么这样设计、每项实验在排除什么、证据如何升级、哪些前提尚未验证，以及哪些竞争解释仍能成立。
- 对承重机制、关键对照、阻断/挽救、时序、剂量、统计单位、外部验证和Supporting Information中的关键证据，应达到能让读者独立重建推理并判断其强弱的粒度。
- 若一项结论需要分成“现象成立”“与机制相关”“机制具有必要性”“可外推”等多个层级，应充分展开，不得为减少篇幅把它们压成一句话。

## 逻辑要求

- 全文应保持“问题从哪里产生—为什么选择当前方案—每一阶段新增什么证据—为什么还需要下一步—最终哪些命题成立”的连续推进。
- 实验先后顺序不自动等于因果链。观察、作者解释、读者判断与证据边界应在语义上清楚可区分，但不必为此机械拆成固定数量的小节。
- 所有批判都应对应具体命题和具体证据。不得只说“机制不够”“对照不足”或“需要更多实验”，而应说明哪条结论因此从什么层级降到什么层级。

## 完整度与字数要求

- 成稿必须覆盖正文、Methods、图注和Supporting Information中所有对主结论有实质影响的证据。补充材料中的承重证据不得因篇幅或位置而略过。
- 字数是完整度的最低防线，不是注水目标。对具有多阶段实验、多模块机制、动物或外部验证及较多Supporting Information的常见机制/材料论文，正文原则上不少于 **20,000个中文字符**；证据链尤其复杂时，应自然扩展到 **30,000个中文字符或更长**。结构简单的短论文可低于该基线，但不得以“论文简单”为由省略关键实验、逐图导读或证据边界。
- 总字数达标不能掩盖局部阶段过薄。对包含多项独立实验、多张主图/补图或承重因果推理的核心阶段，扣除图片链接、表格和图片导读后，原则上应有至少 **2,000个中文字符**的实验设计与证据分析正文；复杂承重阶段应达到 **3,000–4,000个中文字符或更多**。若低于该基线，只能因该阶段确实只包含少量简单证据，不得因为已用表格或图片导读概括而减少正文。
- 不得通过重复背景、复制图注、反复改写同一结论或堆叠通用批判来达到字数。每一段新增的应是设计理解、实验细节、证据关系、竞争解释或边界判断。

## 格式让位规则

- 不可放弃的是：事实准确、证据可追溯、关键图表不遗漏、观察与归因可区分、重要结论有边界。
- 可以放弃或调整的是：普通小节的具体名称、编号、占位句式和示例中的项目数量。
- 不得以“格式让位”为由牺牲重点词汇的必要分组、设计冲突的独立展开、阶段中的完整论证段落、观察与归因的区分及逐图导读。Callout和小标题用于帮助阅读，但不得取代正文深度，也不得成为压缩内容的理由。
- 明确标注为固定的高价值表格原则上保留；但若表格会切断必要的长链推理、造成信息严重压缩或与论文的分支结构直接冲突，应先用完整叙述补足，必要时也可调整表格。

> [!abstract] 优先级顺序
> **事实准确与证据忠实 → 分析深度 → 逻辑闭合 → 内容完整度 → 可读性 → 具体格式。**

# 具体指南

- 本部分使用一级标题 `# 阅读前置｜重点名词、缩写与核心概念`，放在笔记属性之后、正式论文分析之前。
- 开头必须设置“建议怎样使用本模块”提示框，先用一条加粗主轴告诉读者应按什么顺序理解全文。主轴必须来自论文真实设计，不得使用通用套话。
- 名词的组织方式必须服从当前论文，不能预先设定统一分类框架。
- 模板中的 A、B、C、D 只展示“分类后如何排版”，不得直接复制成每篇论文的固定四大类。
- 简单论文可以只设一个名词表；复杂论文可以设置两个、三个、四个或更多类别；某类没有实际内容时必须删除，不得为了凑齐结构保留空类。
- 当文章同时跨越两个以上知识系统、名词超过8项或存在多级对象链时，不得把全部词汇压进一张总表。必须按照本文真实阅读任务分组，使读者能区分研究对象、关键关系/过程、模型与时间条件、以及决定证据性质的方法或指标；分类名称由本文决定，不得直接复制这四个示例名称。
- 每个名词或不可拆的规范复合名称独占一行。不同脑区、细胞群、通路节点、模型、时间概念或方法不得用 `/`、顿号或多个缩写挤在同一“名词/缩写”单元格；即使正文常并列比较，也应拆行后分别解释其位置和作用。
- 凡出现在阶段标题、核心假设、主要 Figure 或承重因果箭头中的术语，原则上必须纳入；复杂论文通常不应只靠少数合并条目覆盖整条主线。
- 分类名称必须从论文真实研究对象和论证主轴中产生，不得跨论文机械迁移。材料文章可按材料组成、功能模块、治疗对象与评价指标划分；机制文章可按研究对象、分子或细胞过程、关键通路与功能终点划分；生信文章可按数据类型、核心算法或指标、候选特征、验证方法与结局概念划分。这些都只是示例，不能直接作为固定标题复制。
- 需要分类时，每个类别使用二级标题并按 `## A.`、`## B.`、`## C.` 顺序编号；不需要分类时可直接在一级标题下放置一个总表。
- 每类使用四列表格。前三列回答“它叫什么”，第四列必须回答“它在本文中具体做什么”。不得只制作中英文词典。
- “在本文中的具体作用”至少说明该名词是研究对象、干预模块、靶点、中继节点、读出指标还是结果终点，以及它位于哪条推理链中。
- 如果同一缩写在不同领域可能代表不同事物，必须说明本文采用的具体含义；作者自定义名称应明确标注“作者命名”。
- 材料或复合干预文章应拆开完整系统、载体、药物和各功能模块；机制文章应拆开关键分子、细胞过程、上下游关系和功能读出；生信或组学文章应拆开数据来源、分析方法、筛选指标、候选特征、验证指标和外部验证概念。
- 只收录理解论文设计和证据链所必需的名词。普通背景词、正文只出现一次且不影响推理的术语，不为增加篇幅而收入。
- 高频实验与分析术语只有在读者需要借此理解证据性质时才保留，并必须写清“实际测量什么”和“不能单独证明什么”。
- 名词解释必须忠实于本文语境。不得把一般教科书定义直接复制过来，也不得把作者尚未证明的机制写成名词本身的既定功能。
- 模块结尾设置“最容易混淆的概念”警告框，优先澄清本文最可能被误读的等号，例如标志物不等于功能、活动相关不等于因果、组合组最好不等于协同、阴性结果不等于等效。
- 对真正承重的关系型概念，表格之后采用“一项辨析—一段解释”：每个Callout只处理一组容易混淆的关系，解释两者区别、本文分别怎样测量、误写后会怎样影响结论。不得把五六个“不等于”压进同一个警告句。
- 所有英文全称、中文名称、上下标、希腊字母、基因/蛋白命名和缩写必须回查正文、图注、Methods及Supporting Information，并在全文保持一致。

# 一、论文定位、灵感来源与核心问题

# 模板

以下模板提供稳定的分析方向，不是要求每篇论文逐格填写的表单。除明确标注为固定的表格外，占位文字只用于提醒可能的分析方向，不限定成稿必须包含的句子、项目、顺序或篇幅。复杂论文应增加层次，相关性弱的组件可删除或合并。

```markdown
# 一、论文定位、灵感来源与核心问题

## 1.0 先把论文放到正确类型中

| 定位问题 | 本文答案 |
|---|---|
| **论文类型** | {{用“研究起点—机制主线—验证终点”定位本文，不只写材料研究、机制研究或生信研究}} |
| **临床/生物学缺口** | {{现有认识、诊断或治疗具体卡在哪一步}} |
| **核心假设** | {{作者认为哪些对象通过什么关系产生什么结果}} |
| **创新的主要类型** | {{概念、机制、策略、材料、方法、算法、数据整合或应用创新；说明主次}} |
| **当前证据层级** | {{本文完成到体外、动物、队列、外部验证、临床或其他哪一级；尚未进入哪一级}} |
| **最小真实贡献** | {{删除包装语言后，数据最稳固地建立了什么}} |

> [!info] 作者声称的创新
> {{忠实概括摘要、Introduction或Discussion中作者对创新性的定位。}}

> [!abstract] 论文实际建立的创新
> {{根据全文证据，说明作者声称中哪些部分真正获得支持。}}

> [!warning] 不应被包装语言掩盖的边界
> {{指出最容易被放大的机制、疗效、预测、泛化或临床外推。}}

## 1.1 作者从什么矛盾出发

{{使用充分的自然叙述还原作者面对的临床、生物学或方法学矛盾。说明已有认识分别解决了什么、在哪些条件下失效、不同限制如何相互作用，以及这些问题为什么迫使作者寻找当前方案。不能只写“疗效有限”“机制不清”或“缺乏有效标志物”。不要为了套用固定公式而压缩中间推理。}}

{{如箭头链、对照表或示意结构确实能帮助读者理解，可以在完整叙述之后自行增加；它们只用于总结，不能替代分析，也不规定固定节点数量。}}

> [!question] 核心问题
> {{用一个可以被本文实验或分析回答的问题，概括整篇论文。}}

## 1.2 灵感是怎样逐层形成的

> [!info] 阅读方式
> 本节不是 Results 顺序预告，也不是用事后结果解释作者“早就知道”什么。它要带读者从初始矛盾进入作者可利用的既有知识、候选模块和设计约束，再一步步看到方案为什么会被构造出来。每个独立灵感点或思路转折使用一个单独小节和至少一个完整段落。

### {{灵感点1｜从哪条已知线索看见了新的可能}}

> [!question] 为什么会想到这一步
> {{说明问题现场出现了什么矛盾，Introduction、既有知识、作者已有技术/材料模块或领域共识提供了什么可利用线索。不得用后文实验成功结果冒充构思来源。}}

> [!info] 这条线索能转化成什么设计
> {{用完整段落解释作者看中了什么性质，它能够解决哪一部分矛盾，需要满足哪些设计条件。}}

> [!warning] 为什么单靠这一点还不够
> {{指出它留下的冲突、不可判别性或实现障碍，并自然引出下一灵感点。}}

### {{灵感点2｜上一点为什么迫使作者增加新节点}}
```

# 具体指南

- 本部分采用“少量硬性结构＋按需展开”的原则。模板提供的是可调用的组织组件，不是必须原样复制的固定目录。
- 必须保留的固定骨架只有四项：论文定位；具体矛盾；灵感如何从问题推进到方案；核心假设、实际贡献与证据边界。它们可以根据叙事需要重新组合小节，但逻辑功能不能缺失。
- `1.0`的定位表格及“作者声称—论文实际建立—证据边界”三层区分属于固定格式，便于不同论文之间稳定比较。
- 灵感形成必须展开，但层数、标题、段落长度和Callout数量不固定。可以两层，也可以八层；重要层可以展开多个段落，次要层不必为了形式单独成节。
- “一点一段”是灵感部分的强制阅读节奏。每个独立的临床/生物学线索、知识连接、目标选择、模块引入、符号矛盾、场景转换或验证策略，都应拥有单独小节或至少一个独立完整段落。段落之间要写出“上一点为什么不够”和“这一点如何引出下一点”。
- 对多模块、多级机制或长因果链论文，灵感形成部分原则上不少于 **1,500–2,500个中文字符**；不得用三个紧凑段落概括五个以上独立的构思转折。
- “设计要求A/B/C”是适合多模块或多场景论文的表达工具，不是每篇论文都必须使用。若使用，数量由真实设计需求决定；若不能在后续实验或分析中找到对应，应删除。
- “核心选择为何有吸引力”“设计冲突”“完整逆向推导”“直接问题与延伸问题”“竞争路线”等属于按需深化组件。能揭示当前论文构思时充分展开；与论文不相关或只会重复前文时删除或合并。
- 表格适合承载稳定映射、模块分工和方案比较；连续推理、灵感转折和前后缺口优先使用叙述与箭头链。不得为了整齐把复杂推理全部压缩成表格短句。
- Callout用于强调作者声称、读者判断、设计要求、证据边界或关键跳跃。它们的类型和数量随内容决定，不得每个小节机械放置一个。
- 小节编号不是硬性槽位。正式成稿可以根据论文自然重命名、合并或增加小节，只要读者仍能清楚看到“问题—线索—设计要求—方案—假设—证据边界”的推进。
- 本部分不是Introduction摘要，而是重建“作者为什么会设计出这篇论文”。正文必须持续回答：前一步已知什么、为什么仍不够、作者因此增加了什么。
- `1.0`先确定论文真正类型。不能只贴“材料研究”“机制研究”“生信研究”等宽泛标签，应写清研究从哪里起步、沿什么主线推进、最后在哪一级终点收束。
- “作者声称”“论文实际建立”“尚未建立”必须分开。前者依据作者原文，后两者依据全文证据，不能把摘要措辞直接当成审查结论。
- `1.1`必须找到具体矛盾。合格的矛盾应包含现有条件、失败位置和未满足需求；“机制不清”“疗效有限”“缺乏研究”本身不合格。
- `1.2`按真实推理层次展开灵感。层数不固定，可以两层，也可以五层以上；每一层都必须由上一层的不足引出，不能写成互不相连的背景知识清单。
- 每层灵感之后尽量提炼一个“设计要求”，说明该线索最终迫使方案具备什么能力。设计要求必须能在后续材料组成、实验分组、分析流程或验证场景中找到对应，不能写成口号。
- 多模块文章应说明作者为什么选择每个现成模块，以及各模块在完整方案中的分工；组合表只在确有多个功能模块时使用。
- `1.3`解释“为什么偏偏选它”。材料文章可解释各组分为何组合、一个模块为何不能独立完成任务；机制文章可解释为何选择该靶点、通路或细胞过程；生信文章可解释为何选择该数据类型、特征、算法或验证路线。这些只是示例，标题和层级必须服从具体论文。
- `1.4`只写真实存在的设计冲突，例如稳定性与释放、杀伤与安全、灵敏度与特异性、模型复杂度与可解释性、拟合能力与外部泛化。没有真实冲突时可以删除，不得机械凑数。
- `1.5`用一条完整箭头链把临床或生物学起点推导到本文方案，使读者看到每一步为什么必然引出下一步。随后必须区分“作者明确陈述”和“基于论文结构的合理重建”，不能虚构作者真实思考或研发时间线。
- “论文真正的问题”“论文直接研究的问题”和“论文延伸提出的问题”必须分开。直接问题只能使用本文真实模型、数据和终点；未被实际建模或测量的临床结果只能放在延伸问题中。
- `1.6`把核心假设拆成彼此可部分独立成立的嵌套假设。材料形成、功能改善、机制归因和体内有效可以分别成立，不能用最终效果反推所有中间机制都正确。
- 可证伪命题优先写时间先后、剂量关系、模块删除、必要性、充分性、阻断、挽救、外部验证和泛化预测，而不是把作者结论换一种说法。
- “最大的因果或证据缺口”只选最承重的一处：如果补不上，作者最重要的增强版结论就不能成立。
- `1.7`分别给出“最小可成立贡献”和“增强版贡献”。前者必须在删除最弱机制和包装语言后仍由数据直接支撑；后者要明确还缺什么证据才能成立。
- `1.8`比较的不是空泛优缺点，而是说明成熟替代路线能否更简单地解释或解决同一问题，以及本文还缺什么直接基准才能证明增量价值。
- 材料文章的现实基准可以是游离药物、空载材料、缺失模块、标准治疗或同类平台；机制文章可以是替代通路、遗传与药理正交方案；生信文章可以是简单基线模型、现有评分、外部队列或公开工具。
- 本部分可以较长，但每一段都必须服务于“问题如何生成方案”。不得提前进入逐Figure复述，也不得用后见之明把尚未验证的机制写成设计起点时的既定事实。

- 本部分的任务是建立全文导航，不是提前代替后面的逐阶段、逐实验分析。表格只写足以帮助读者把握全局的信息，实验细节、对照任务和就地批判留到相应实验处展开。

- `2.1`按需使用。论文没有机制总图、Graphical Abstract或Scheme时直接删除，不自行生成一张假装来自论文的图片。图片导读必须提醒读者：工作模型不是证据。
- `2.2`必须覆盖全文主线和重要支线，但表达形式不固定。线性论文可以使用箭头链；存在并行模块、发现—验证支线或多队列结构时，应使用分支、分段或主线/支线叙述。
- `2.3`使用固定五列表格。每一行必须说明上一节点留下的真实缺口，以及下一步带来的证据升级；不得写成“进一步验证”“继续探究”等空话。

- `2.4`的表达方式保持灵活。因果关系可以是单链、并行链、分支、反馈或条件依赖；不得为了排版整齐把复杂关系强行压成一条直线。
- `2.5`使用固定五列表格，只审查真正承重的箭头或推理跳转，不要求把全文每个相关性都塞入表格。“是否闭合”必须依据证据性质判断，不能根据作者措辞判断。
- `2.6`是按需模块，但一旦使用，表格列固定。材料文章可拆分载体、药物和功能模块；机制文章可拆分关键节点和中介过程；生信文章可拆分数据来源、候选特征、算法组成和验证环节。简单论文不需要为了形式保留此表。
- `2.7`使用固定六列表格，承担后续章节的导航作用。阶段应按真实科学问题划分，不按Figure编号机械划分；“承重墙证据”只写该阶段不可轻易替代的关键实验或分析。
- 本部分不设置“主要对照组总表”。每个对照的唯一变化、判别任务、可排除内容和残余混杂必须放在具体实验发生处分析，避免脱离实验语境列名单。
- 主文和Supporting Information中的承重证据都必须进入推进顺序、因果状态或阶段导航；不能因为位于补充材料就从全文地图中消失。

# 三、阶段主体｜逐实验复原设计、结果与证据边界

# 模板

阶段主体写成完整的“证据教学单元”，让读者沿着作者的设计问题逐层进入，而不是直接接收结果摘要。二三级标题负责呈现逻辑台阶，Callout 突出关键判定，表格稳定比较，完整段落承担解释。不得为追求统一外观机械规定 Callout 数量。

这里的逻辑由阶段 1、阶段 2、阶段 3……分别完成，但不得把模板语言复制进成稿。每个阶段自身都要通过当前论文的具体对象、矛盾、实验和数据自然呈现“问题—思路—方案—判定—结果—评价—残余问题—下一步”，不能写成“本阶段将依次……”的元说明。阶段应像灵感部分一样逐步引出：上一阶段留下哪个具体问题，作者因此形成什么具体解决思路，为什么选择当前方案和对照，结果是否达到判定，方法本身是否可靠，又暴露了什么新问题。

# 具体指南

- 这一部分是全文主体。阶段数量、每阶段的实验数量、小节标题、Callout数量和图片位置均由论文决定；不得为了套模板压缩复杂证据链。
- 阶段 1、阶段 2、阶段 3……必须分别完整覆盖“问题—思路—方案—判定—结果—评价—残余问题—下一步”。验收时逐阶段单独检查，不得把不同阶段合并后检查，也不得因某项已在前一阶段出现而在后一阶段省略。
- 八项闭环是内容验收清单，不是正文措辞清单。禁止向读者宣布“以下先写……再区分……最后说明……”，目录和正文只呈现本论文的科学内容。
- 正式写作前先在内部建立八格阶段卡，每格用本阶段的具体对象、比较、方法或结果填写；再将其改写为连续叙事并删除阶段卡。若任一格只能写出“相互补充的实验”“跨方法一致”“新增判别力”等通用语，说明尚未理解该阶段，必须回到证据底稿。
- 阶段前两段原则上先完成“具体已知—具体未知—为什么重要—作者用什么具体思路破解”，不得先给整阶段综合批判。批判在相关结果之后就地出现，再于阶段末整合。
- 做删句测试：删除一句后若不损失本论文事实、设计选择的因果理由或证据边界，该句没有信息价值，应删除。尤其删除向读者汇报章节安排的句子。
- 若两个阶段出现相同或仅替换名词的完整句段，默认判为模板污染；共同逻辑必须分别落成各阶段真实的科学问题与方法选择。
- 灵感与阶段深度是阻断项。三个以上灵感点时灵感有效叙述通常至少 1200 字符、单个承重点通常至少 220；包含两张以上数据图的阶段有效叙述至少 2000，复杂阶段达到 3000–4000。表格、图片链接、标题和Callout标签不计入有效叙述。
- 禁止用一组极短的固定功能小节先概括全阶段、再在后面重复展开。每个真实子问题应在自己的小节中充分完成问题来源、方案选择、图证、评价和过渡。
- 模板中的“实验拆解—设计完整性—正反判定—逐项证据—观察—作者推理—隐藏前提—阶段评价—下一实验—阶段推进”是上述八项的展开方式；每个阶段格式可适配论文，但不能压成少量入口 Callout 和若干结果段落。
- 上述闭环必须在阶段内部反复可见，而不只是功能齐全。每个承重小节开头用具体缺口启动，正文呈现解决思路与方案选择，结尾评价是否解决、方法是否充分和下一问题；读者只读各小节首尾也应能复原完整推进链。
- 阶段入口的“如何发现”不是要求虚构作者真实时间线。优先使用作者明确动机；若依据结果结构逆向复盘，必须写成“从论文设计可以重建为……”并与作者明说分开。
- 标题完整性是全文硬规则，适用于所有一级、二级和三级标题。每个标题后必须出现与标题直接对应的实质内容；不适用于本文的标题必须删除，不得保留空壳。
- 标题后不得立即进入下一个标题，也不得只放一张表、一张图片、一个链接、一句定义或一句泛泛结论便结束。表格、图片和Callout可以辅助正文，但标题下必须有足以解释该标题为何存在的完整叙述。
- 标题内容必须兑现标题中的全部承诺。若标题包含“为什么”“如何”“是否成立”“证据边界”“设计冲突”等判断词，正文必须实际回答相应问题，并给出理由或证据；不得只换一种措辞重复标题。
- 不以统一字数机械验收所有标题，但出现以下任一情形默认判定为敷衍：只有一两句通用表述；没有本文对象、实验或证据；可以原封不动复制到任意论文；只复述图注；只给结论而没有推理。复杂承重标题通常需要多个完整段落。
- 每个核心阶段必须存在独立于图片导读的“逐实验证据分析正文”。图片后的面板表、take-home message、补图简介和阶段性评价都不能替代这部分正文。若一个阶段主要由图片链接、短表格和一句话补图摘要组成，默认判定为展开不足。
- 每个核心阶段必须形成可追踪的证据递进，但不强制先列问题清单，也不规定问题数量。若问题导航能帮助阅读，可以列出；若连续叙述或直接以判别任务命名小节更自然，则不必列清单。
- 阶段的小节及段落应共同完成“为什么此时必须做—作者怎样设计及为何这样设计—实际得到什么—这些结果能说明什么—为什么仍然不够—下一组实验因何出现”的推进。该顺序是逻辑要求，不是固定标题或逐项填空格式；可以回返、分叉、合并或调整次序，但各次证据升级之间必须讲清因果关系。
- 每一组承重实验结束后，都要交代它解决了前面的哪一层疑问、留下了什么缺口，以及这个缺口如何推动后续实验。不得只用“为了进一步验证”“随后作者检测了”连接彼此独立的结果块。
- “为什么这样做”至少有两个层级：一是本阶段为何在全文此处出现，二是阶段内部每组实验为何必须先于或后于另一组实验。只解释研究背景而不解释实验顺序，仍属于逻辑展开不足。
- 每一个证据阶段都必须大致完成以下闭环：这一步要回答什么、作者为什么这样安排实验、各实验分别测量什么并承担什么判别任务、什么结果支持或削弱假设、实际观察、作者由观察得出的结论、审查后的支持上限、关键隐藏前提或替代解释、阶段性批判、最有判别力的后续实验，以及结果怎样推动到下一阶段；确有可复用方法论时再增加可迁移的设计启发。不同阶段可以调整篇幅、顺序和表现形式，但不能整体缺失关键推理，也不能只在阶段末尾用一段总评替代逐步分析。
- “实验判别逻辑”不能只写预期成功结果，还要写替代解释成立或设计失败时可能出现的模式。正反预期用于解释为什么需要多种正交实验和关键对照，而不是事后按作者结果倒推标准。
- “实际观察—作者结论—审查判断”是阶段阅读节奏的基本单元。对于复杂阶段，应围绕各组承重实验重复出现，而不是把全阶段观察集中成一份长清单、再在结尾一次性评价。
- 同一内容只承担一次主要表达任务：实验分工表不重复正文结果，逐图表不重复实验设计正文，阶段性评价不再逐条复述观察，跨阶段过渡不重新写一遍阶段总结。允许必要引用，但不得换一种格式重复同一段信息来制造篇幅。
- 阶段排版必须让证据升级在目录层级上可见。凡是从“相关到连接”“连接到功能”“功能到时序”“时序到必要性/充分性”“表型到机制”“体外到体内”或其他不同证据性质的跨越，原则上分别设置独立的二级或三级小节。不得把三种以上证据性质压进一两个长段落，再连续附上所有Figure与Figure S。
- 阶段内部的问题数量与小节数量由论文决定，不预设三步、九步或固定目录。材料身份可能沿“形成—组成—负载—释放”推进，神经环路可能沿“解剖—突触—活动—因果”推进，生信研究可能沿“发现—筛选—内部验证—外部验证”推进；这些只是理解证据升级的示例。
- 当一个问题确实适合突出时，可以使用“一问一答”Callout；当连续论证更自然时，应使用完整段落和有意义的小节。不得为了增加Callout数量切碎论证，也不得用两段总述加连续图片代替阶段正文。
- 每个证据小节开头先写它承接的缺口，结尾写它新留下的缺口；中间只处理服务于当前升级的实验、数据和图片。这样使读者仅看小标题与首尾句，也能复原“上一证据为什么不够—下一证据为什么出现”的推进链。
- 小节之间禁止只写“为了进一步验证”“随后作者又检测”。连接句必须点名前一方法的证据上限、当前方法新增的判别能力，以及证据性质发生了什么升级。
- Callout 首行严格使用 `> [!type] 标题`，后续每行均以 `>` 开头，段间空行写为 `>`。逐面板表默认置于 Callout 外；Callout 内表格必须每行带 `>`。任何裸 `[!type]` 都是格式错误。
- Figure与Figure S必须就地嵌入它真正服务的证据小节。若一张主图跨越多次证据升级，应在相关小节分别引用或分析对应面板，不能为了保持整图只出现一次而把所有实验正文和补图集中到阶段末尾。
- 以下结构默认判为不合格：阶段标题后用一至三个超长段落概括全部实验，随后连续排列多张主图/补图，最后直接进入下一阶段；即使事实、表格和take-home message齐全，也属于逻辑排版未展开。
- 阶段中不得出现“一段总述后立即连续嵌入多张Figure/Figure S”的结构。图片只能出现在它所回答的具体问题之后，且图片导读不得切断问题之间的逻辑过渡。
- 每项具有独立自变量、对照任务或证据性质的承重实验，都要在阶段正文中实际分析：为什么需要它、如何设计、关键对照在区分什么、实际数据如何、作者如何归因、证据能到哪里。可以自由组织句式和小节，但不得仅在Figure面板表中用一行完成。
- 对原文明确报告的关键结果，应尽可能给出实际组别、方向、n、效应量/数值、精确P值或置信区间。若原文只有图形而无可靠数值，应如实写“图中显示方向，未报告可提取的精确效应量”，不得用“显著改变”代替数据。
- 阶段必须按“真实科学问题”划分，而不是按Figure 1、Figure 2或Results自然段划分。一张Figure可以服务多个问题，一个问题也可以同时使用主文和SI多张图。
- 每个阶段的开头要让读者明白“为什么现在要做这组实验”。已有证据、未决问题、竞争解释和判定标准是常用思考方向，但不要求固定顺序、固定数量或逐项显式填写。
- 先用完整叙述还原设计逻辑，再使用表格稳定比较。不得把全部分析压缩成表格短句。
- “实验或分析—直接测量—推理任务—不能单独证明”四列表是本阶段的基础映射表；实验复杂时使用七列完整性表，简单阶段不强制使用第二张表。
- 对照必须在具体实验中就地分析：说清唯一变化、判别任务、已排除什么、仍未排除什么。不再另列脱离语境的全局对照组清单。
- 承重实验需要让读者能区分数据本身、作者解释和审查后的证据边界。可以分成多个Callout，也可以用连贯段落完成；重点是不把观察与归因写成同一件事。
- “实际观察”优先报告定量值、效应方向、效应量、时间、剂量、置信区间和统计单位；不得用“明显改善”“显著激活”取代关键数据，也不得在观察层写入机制。
- 不设置孤立的“逐图与 Supporting Information 证据审查”大章节。全部 Figure、Scheme 和 Figure S 必须嵌入它们服务的具体阶段和判别任务附近；边讲思路、实验与证据，边讲图。
- 每张承担正文论证任务的 Figure 或 Figure S 必须单独命名，并按“图片内容介绍—逐面板完整分析表—真正 take-home message”导读。不得用一段 a–d/e–h 概括替代逐面板表。
- 每张包含实验数据的 Figure 或 Figure S 都必须覆盖原图全部面板。原则上 a、b、c 逐行介绍；只有连续面板实验、条件和判别任务完全一致时才可合并，并明确列出范围。补图与主图使用相同标准。
- 复杂Figure可将承担同一判别任务的连续面板合并为逻辑面板组，但不得因为合并而遗漏关键对照、剂量、时序、n或统计单位。单面板图不得省略表格，只是表格可缩短为一行。
- Scheme、Graphical Abstract和纯机制示意图若不包含实验数据，可不使用逐面板表，但必须明确标注为工作模型而非证据。
- 若同一Figure包含属于不同科学阶段的实验，不得因图片只在前文嵌入过一次，就将后续阶段的面板分析留在前一阶段。可在后续阶段重复嵌入整图、引用已嵌入图片或只重新分析相关面板，但每个面板的实验设计与证据判断必须出现在它真正服务的科学阶段中。
- “在故事中的任务”不是再写一遍测量方法，而是说明该面板用于确认身份、排除毒性、建立时序、支持必要性、验证外部泛化或完成其他何种证据升级。
- “真正take-home message”必须是证据审查后的综合判断，不是复制论文图题或作者结论。它应同时写清“这张图建立了什么”与“它没有建立什么”。
- Scheme、Graphical Abstract和机制总图仍要做整图定位，但若其面板只是概念绘图而非数据，可不使用逐面板证据表；必须明确标注为作者提出的待验证模型，不能当作证据。
- Supporting Information不按附录集中处理。承担样本排除、剂量筛选、方法验证、机制阻断、额外模型或安全性的SI图，必须放到相应实验处同等分析。
- 阶段性评价应围绕具体命题，避免给出脱离对象的笼统等级。同一阶段对不同命题可以作出不同判断，也可用连贯论证取代逐项评分。
- “最有判别力的下一步实验”应超越“增加阻断实验”这类笼统建议。根据具体问题选择必要的分组、时序、等条件、读出或预测，让读者理解它如何改变当前判断；不要求每项建议都使用同一组技术要素。
- 阶段结尾应与全文论证保持连接。可以引出下一阶段，也可以写分叉、回返验证或当前主线的收束；不要为了固定句式伪造线性叙事。
- 每个阶段都保留“可迁移的设计原则”这一检查位置。确有可复用原则时具体提炼；确实没有时简要说明本阶段为何无须单独提炼，不得用空泛套话凑数。

# 六、竞争性解释与双向压力测试

# 模板

```markdown
# 六、竞争性解释与双向压力测试

## 6.1 先把作者的论证建立到最强
```

# 具体指南

- “双向”意味着先帮助作者建立最强版本，再使用同等严格的竞争解释施压。不得把钢人写成赞美，也不得把红队写成零散挑错。
- 最强版论证必须尊重证据边界。钢人不是替作者补上并不存在的实验，而是找到现有数据能支持的最强連贯解释。
- 竞争模型必须足够具体，能解释多个已有结果并产生与主模型不同的可测预测。“可能有其他通路”不是合格的竞争模型。
- 优先审查因果方向、时间顺序、剂量/暴露差异、模块物性变化、测量偏差、模型自然恢复和共同上游原因，而不是只问结果是否显著。
- 分叉实验必须能让主模型和竞争模型对结果做出不同预测。如果无论什么结果都被解释为支持主模型，该机制就没有真正被检验。
- 最小可发表故事不应故意贬低论文；它的任务是识别“不依赖最脆弱机制仍然成立的真实贡献”。
- 主模型简单、证据很强的论文可减少竞争模型数量；机制复杂、多模块或强外推论文应充分展开，不受表格示例行数限制。
- 竞争解释有效叙述通常不少于1000个非空白字符；模型表和分叉实验表不计入该叙述门槛。复杂论文通常至少两个实质竞争模型；不足两个时说明为何没有第二个同等有力的模型。
- 每个模型至少解释两项承重观察，并给出与主模型不同的可测预测。只解释一个孤立异常、没有生成机制或没有差异预测的内容属于一般局限，不算竞争模型。

# 具体指南

- 最值得学习的是研究者如何把问题转化为可判别的实验与逐级证据，不是把论文使用的技术名词重新列一遍。
- “已完成”与“未完成”必须相互对应，不能前者过度赞扬、后者无限抬高标准。
- 最终复盘是对整套设计逻辑的高密度压缩，不是摘要的另一种写法。可以是一句话，也可以是一小段；应自然体现研究价值与最重要的证据边界。
- 最终复盘有效叙述通常不少于800个非空白字符；命题表、Callout和列表不计入该叙述门槛。
- “真正完成”与“尚未证明”逐项对称，至少覆盖稳健核心、条件性结论、脆弱机制和未建立外推；不是将前文结论复制粘贴到两个栏目。
- 必须指出全文最关键的一个因果断点，并解释哪项证据最能改变判断；不得只写“仍需更多研究”。

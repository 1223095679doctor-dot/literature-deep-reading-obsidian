## 1. 来源边界

- 执行规范和模板决定流程与成稿；历史范例只决定深度标尺。
- 新论文正文、SI、直接配套附件和经核实的正式元数据才是事实来源。
- 根据题目、作者、DOI、期刊、正文引用和版本标记确认文件身份。
- 范例中的事实、数值、句子、判断、图片和参考文献绝不能迁入新笔记。

## 2. EOF 与截断处理

完整读取必须同时满足：总页数可验证、第一页至末页连续覆盖、末页实际读取、最后一个图表/方法/附录/数据声明入账、异常页视觉复核完成。

出现句子中断、页码范围不符、图注或表格无故中止、返回量异常或工具提示 truncated 时：

1. 假定输出不完整；
2. 找到最后一个确认完整的位置；
3. 缩小页码或改单页读取；
4. 保留边界重叠；
5. 重新核实连续覆盖。

OCR 只用于索引。剂量、基因/蛋白名、数值、统计符号、希腊字母、上下标和图号必须回看页面。

## 3. 内部台账

至少记录：

| 台账 | 必需字段 |
|---|---|
| 页面 | 文件、总页数、范围、方式、截断、视觉复核、EOF |
| Figure | 图号、面板、页码、图注、实验、分组、n、提取状态 |
| 实验 | 对象、处理、时序、组别唯一变化、读出、n/重复、来源 |
| 方法 | 实际测量对象、参数、样本处理、归一化、统计、报告缺失 |
| 命题 | 支持证据、证据性质、阴性证据、替代解释、缺失判别证据、边界 |
| 推进 | 前一步已知、当前缺口、实验如何改变证据、新问题与后续关系 |
| SI | 项目、页码、论证任务、删除后影响、目标阶段、纳入状态 |

台账是内部工作文件，禁止进入最终目录。

## 4. 图片与 SI

- 提取全部主图、Scheme、Figure S/Scheme S；承重 Table 即使不转图也必须分析。
- 边界不确定时保留高清整页，优先于冒险裁掉 panel、坐标或图例。
- 已安装 `sci-figure` 时可用其获取无页眉正文的高清原生图，但仅作为候选增强结果。先独立建立预期图号清单，再逐图核验 panel、图例、坐标、比例尺和统计标记；任何漏图、错配或裁切不全均回退到原流程，禁止把“工具检测为 0”解释为“没有 Figure”。
- 图片按原图号命名，不按章节重编号。
- SI 中承担剂量筛选、操控有效性、机制阻断、消融、挽救、额外模型、安全性或 QC 的证据，与主文同等处理并就地放置。
- 每张含数据大图必须单独命名、就地嵌入证据阶段，并有逐面板读图导航表和独立 take-home message。默认五列为“面板、图中具体展示什么、这张图应该怎么看、关键变化或数值、读图结论与易误读边界”；可按材料表征、生物学定量或显微/组织图使用专用五列表头。完整实验设计与证据批判放在阶段正文，不在表中重复。
- 禁止另设孤立、重复的“逐图与 Supporting Information 证据审查”大章节。

## 5. 写作许可门

禁止“先根据摘要和主图写一版，再补 Methods/SI”。只有来源、EOF、台账、阶段地图和异常处理全部完成后才能写最终正文。

写作许可门是内部状态，不要求用户逐项确认；仅在文件缺失、损坏、加密或身份冲突无法解决时暂停并请求补充。

## 6. 交付边界

- YAML frontmatter 必须是文件首行。
- 核心文件固定命名 `设计思路与证据审查.md`。
- 最终文件夹的 `YY.MM.DD` 使用创建笔记时的当前本地日期；论文正式发表日期只写入 frontmatter 的 `published`，不得用于文件夹前缀。
- Figure 使用 `![[Figure/Figure 1.png]]` 形式的 Obsidian 内链。
- Source 保留原始正文和 SI，不修改内容；必要时记录哈希。
- 最终目录只保留核心 Markdown、Figure 和 Source。

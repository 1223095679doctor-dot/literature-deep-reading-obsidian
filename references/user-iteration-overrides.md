# 用户迭代规则（最高优先级）

本文件记录真实试跑后由用户确认的修正。它高于较早的启动提示、执行说明、范例和模板历史表述；事实准确与证据忠实仍为最高科学原则。

## 1. 文件夹日期

- 最终文件夹 `YY.MM.DD-论文中文题目` 使用创建本次笔记时的当前本地日期。
- 不使用论文发表日期作为文件夹前缀。
- 论文发表日期只进入 YAML frontmatter 的 `published`。

## 2. 第三部分的阶段入口

- 每个阶段不能直接进入结果压缩或审查结论。
- 阶段必须形成完整的层层递进单元：必须回答的问题/前一步缺口 → 实验任务拆解 → 设计与报告完整性 → 成功/失败判定 → 实际观察 → 作者推理 → 隐藏前提或推理跳跃 → 阶段性评价 → 最有判别力的下一步实验 → 结果怎样推动到下一阶段。
- Callout、二三级标题、自然段和表格按内容选择。Callout 用于突出入口、观察、作者推理、隐藏前提、评价与实验建议，但不得为了固定数量机械切碎正文。
- 阶段开头必须回答问题怎样被发现/定位、为什么必须做当前实验、方案怎样设计及正反判定标准；可采用“问题列表＋阶段入口 Callout＋实验映射表＋预期/失败 Callout”的组合。
- “发现路径”若非作者明确陈述，标为基于论文结构的逆向重建，不虚构真实研发时间线。

## 3. Figure 就地整合与逐面板分析

- 不再设置孤立、重复的“逐图与 Supporting Information 证据审查”大章节。全部 Figure、Scheme 和 Figure S 嵌入它们真正服务的证据阶段，边讲思路边讲图。
- 每张大图必须单独写出完整图名，例如 `Figure 2`、`Figure S6`、`Scheme 1`，不能把多张图合并为一个笼统图片块。
- 每张 Figure 和 Figure S 提供基础图注式导读，让读者知道 a、b、c 各画了什么、组别/条件、坐标颜色标记和直接观察。
- 每张含数据大图使用一张逐面板“读图导航表”。默认五列为：`面板｜图中具体展示什么｜这张图应该怎么看｜关键变化或数值｜读图结论与易误读边界`。阶段正文负责完整实验设计、因果推理和证据审查，逐图表不再重复一遍“对象/条件—故事任务—支持—不能支持”。
- 可按图片类型改写五列表头：材料表征图用“技术与图中内容—看什么特征—实际结果—结构判断与局限”；生物学定量图用“对象与读出—关键比较—实际结果—生物学含义与边界”；显微/组织图用“颜色与标记对象—区域和组别—可见变化—量化要求与取景偏倚”。列名必须服务读图，不能为了统一外观强行套用不合适字段。
- 原则上逐面板列行；仅在连续面板实验、条件和任务完全相同时合并。
- 最后写整图 take-home message。

## 4. 灵感形成

- 灵感部分要引导读者理解方案的设计思路怎样从问题、已有知识、可用模块和设计约束中形成。
- 不把实验验证顺序或 Figure 结果改写成灵感来源。
- 每个灵感点写清：为什么想到、能解决什么、单独为什么不够、下一转折怎样出现。
- 严格区分作者明确写出的动机与 Agent 的逆向设计复盘。

## 5. 阶段必须持续呈现问题驱动的递进

- **作用单位是单个阶段，不是整篇阶段主体。** 阶段 1、阶段 2、阶段 3……每一个阶段都必须各自独立、完整地形成一次闭环：`问题 → 思路 → 方案 → 判定 → 结果 → 评价 → 残余问题 → 下一步`。禁止把“问题”集中在阶段 1、“方案”放在阶段 2、“结果/评价”拖到后续阶段，或只有全部阶段合起来才凑齐闭环。
- 每个阶段内部都要让读者持续看见：本阶段的问题怎样从前一阶段产生，作者形成了什么解决思路，选择了哪些实验方案和关键对照，事先如何判定成败，实际结果是什么，结果与方法是否足以解决本阶段问题，还留下什么，以及为何进入下一阶段。
- 八项功能在每一个阶段中都要清楚可定位。标题可按论文真实对象改写、合并相邻项，但不能因为整篇其他阶段已经出现过某项功能，就在当前阶段省略它。
- 阶段内部若有多次证据升级，可在这个“大闭环”内继续形成小闭环；小闭环不能取代该阶段自身完整的八项结构。
- 禁止使用“为了进一步验证，作者又……”作为主要连接方式。必须明确：前一证据不能区分哪两个解释，新增实验改变了什么证据性质，为什么该方法比直接重复前一方法更有判别力。
- 阶段开头不只列问题，还要用完整段落逆向还原作者如何定位该问题及为何采用这一总体路线；非作者明说的内容标为结构复盘。
- 对复杂阶段，应在完整阶段闭环内部围绕每次证据升级重复小闭环，而不是在入口统一写设计、中央堆全部 Figure、结尾统一写批判。

## 6. Obsidian Callout 与图片注释格式

- Callout 首行必须严格写成 `> [!type] 标题`；禁止裸写 `[!type]`、写进代码围栏或在 `>` 前使用列表缩进。
- Callout 的每一行正文都必须以 `>` 开头；段落间空行写成单独的 `>`。不要依赖普通空行后的隐式延续。
- 图片基础介绍使用短 Callout；逐面板 Markdown 表格默认放在 Callout 外，避免引用层级导致 Obsidian 显示原始代码。
- 只有确有必要才把表格放入 Callout；此时表头、分隔行、每条数据行及空行都必须逐行加 `>`，且各行列数一致。
- 图片嵌入使用 `> ![[Figure/Figure 1.png]]` 仅当它属于前一 Callout；更稳妥的默认形式是独立图片链接，再另起图片介绍 Callout。

## 7. 重点名词必须稳定、分组且不拥挤

- 复杂论文只要跨越两个以上知识系统、存在多级对象链或核心术语达到 8 项，就必须按论文真实知识系统分成至少两个有意义的类别；不得把所有词压进一张总表。
- 每个名词或一组不可拆的规范复合名称独占一行。不得用 `/`、顿号或多个缩写把不同节点、不同细胞群、不同模型或不同证据概念挤在同一单元格。
- 神经环路论文通常需要把脑区/细胞群、通路关系、时间与疾病模型、操控/记录技术分开；这只是路由提示，正式分类必须服从当前论文。
- 每个承重名词的“本文作用”至少交代：它是什么、位于哪条链、本文怎样测量/操控、它能承担什么判断；不确定或非承重项不得用合并条目掩盖。
- 名词数量以“足以独立读懂主线”为准。若一个术语在阶段标题、核心假设、主要 Figure 或因果链中承重，原则上必须进入本模块。
- 易混关系采用“一组关系一个 Callout、一段完整辨析”，禁止把多个不相关的“不等于”挤进同一个警告框。

## 8. 禁止把写作规则写进成稿

- “问题—思路—方案—判定—结果—评价—残余问题—下一步”是幕后组织规则，不是正文口号。禁止在阶段开头解释“本阶段将先写什么、再写什么、最后写什么”。
- 禁止出现可跨论文、跨阶段原样复制的元叙述，包括“本阶段必须回答的问题来自前一步仍然不够的证据”“作者的解决思路是把该缺口拆成相互补充的实验任务”“以下先写实验设计与报告完整性”“阶段性评价将明确……”。
- 每个阶段直接从论文特异的科学矛盾开始：已经观察到什么、哪两个具体解释仍不能区分、该不确定性为何阻碍核心结论。随后用当前论文的真实对象与方法引出解决思路。
- 八项功能必须由论文特异内容兑现，不能靠出现“问题、思路、方案、判定”等标签过关。删除一切不增加论文信息、设计理解或证据判断的过渡句。
- 阶段不得上来先作综合批判。先让读者理解科学问题和作者方案，再在相应证据之后评价；批判回答“这项结果离本阶段问题还差什么”，不能抢在问题和方案之前。
- 同一段或高度相似段落不得在多个阶段重复。若一句话替换阶段编号后仍可用于任意论文，应改成当前阶段的具体问题、具体选择和具体判别逻辑，或直接删除。

## 9. 逐面板表禁止无信息占位

- “图中具体展示什么”或对应的图片类型专用列，必须具体回答该面板画了什么：实验流程、代表图、定量曲线、坐标含义、标记对象或比较关系。
- 禁止填写“见图及图注”“见原图”“本行按对应面板读取”“详见论文”“同上”“如图所示”等把阅读任务推回给读者的废话。
- 若来源不足以可靠确定面板内容，回到原图或图注重新核验；仍不能确认时明确写出无法识别的原因，不得用占位语伪装完成。
- 每个单元格都必须新增与该列对应的信息。某列确实不适用时写具体理由；不要用破折号或复制相邻列内容填充。
- 禁止在不同面板反复填写“论文相应对象与组别”“按作者报告方向分离”“提供空间或形态证据”“不能证明完整机制链”等跨图通用句。无法写出该面板特异内容时，必须回查图片、图注、正文和 Methods，而不是用套话填满表格。
- 含数据 Figure/Figure S 必须严格“一面板一行”。a、b、c、d 分别成行；禁止 `a–d`、`a/b`、`a、b` 等范围或组合行。即使连续面板属于同一实验，也要分别写清各面板呈现形式、直接观察和证据任务；共同条件可精炼重复，但不能合并面板。
- 一个字母面板内部若由若干不可分割的小视野或同一坐标的配对图组成，可保持一行；判定单位是原图正式面板标签，而不是视觉上有几张小图。
- Figure S 不得降级为“一张补图一行”的总表。凡包含多个正式面板标签，同样建立逐面板表，标准与主图一致。

## 10. 灵感与阶段深度是阻断项

- 灵感和阶段是全文重点。目录正确、Callout齐全、八步闭环出现或逐图表完整，都不能替代分析深度。
- 每个灵感点至少充分展开：线索从哪里来、为何与当前矛盾相关、怎样转化为设计要求、单独为何仍不够、下一转折怎样产生、这一复盘的证据边界。不得用一个短段同时压缩全部功能。
- 灵感部分要达到两份优秀范例的推演密度；若有三个以上灵感点，扣除表格/Callout标记后的有效叙述通常不得少于 1200 个非空白字符，单个承重灵感点通常不得少于 220 个字符。只能靠具体推理增加深度，禁止重复背景注水。
- 每个包含多项实验或两张以上数据图的核心阶段，扣除标题、图片、表格和Callout标签后的有效叙述不得少于 2000 个非空白字符；复杂承重阶段应达到 3000–4000 或更多。低于 2000 默认阻断交付，不能仅给 warning。
- 深度至少体现为：问题为何成立、方案选择相对替代方案的理由、关键对照的唯一变化、正反预测、定量观察、作者归因、逐项证据上限、竞争解释、残余缺口和判别实验。增加图注转述或表格短句不计入深度。
- 禁止先用一组极短的“问题/实验/预期/观察/下一步”小节概括整个阶段，再在无标题正文中重复展开。应让每个真实科学问题对应一个充分展开的小节，边引出、边设计、边看图、边评价，再自然进入下一个问题。

## 11. 竞争解释与压力测试必须形成真正模型竞争

- 本节是阶段主体之后的第二分析核心，不是“还可能存在其他机制”的可能性清单，也不是把前文缺点重新汇总。
- 先钢人化作者模型：明确在不补造证据的前提下，现有数据能承担的最强连贯论证、最难被替代的证据组合和仍稳固的最小贡献。
- 每个竞争模型必须具体说明：替代因果链或生成机制、能同时解释的至少两项承重观察、解释不了的观察、与作者模型共享的预测、真正不同的可测预测。不能同时解释多项数据的零散猜测不进入竞争模型表。
- 至少选择一个最有威胁的竞争模型进行深挖：若它成立，逐条说明哪些结果仍保留、哪些机制措辞降级、哪些结论完全失效。
- 分叉实验必须写清对象、分组、唯一变化、时序、等条件、读出，以及结果A/B分别支持或削弱哪个模型；若两种模型对结果没有不同预测，该实验不具有判别力。
- 复杂机制、多模块或强外推论文通常至少提出两个实质竞争模型；简单论文可少于两个，但必须说明为什么没有第二个同等有力的模型。
- 有效分析叙述通常不得少于 1000 个非空白字符；模型表和分叉实验表不能替代正文推演。深度来自模型解释范围和差异预测，不靠罗列一般局限。

## 12. 最终复盘必须重新分级全文命题

- 最终复盘不是摘要、Discussion改写、阶段结论拼接或“优点/缺点”清单，而是站在全文证据审查之后重新判断每个承重命题的状态。
- 至少分成四层：即使主机制错误仍成立的稳健核心；依赖未验证前提的条件性结论；一项分叉实验失败就会断裂的脆弱机制；本文未直接检验的外推。
- “真正完成了什么”与“尚未证明什么”必须逐项对称。每项写清对应命题、承重证据、支持上限、关键缺口和适当措辞；禁止一边宏大赞扬、一边用通用清单无限抬高标准。
- 必须指出全文最关键的一个因果断点：它位于哪条箭头、为什么现有证据不能闭合、补上什么证据会最大幅度改变评价。
- 必须提炼最值得迁移的设计原则及最容易误学的做法，解释“为什么”，不能只列技术名称。
- 最后给出高密度总判断，同时包含研究构思、最稳固贡献、最大因果边界与下一关键问题；不能只复述题目或摘要。
- 有效分析叙述通常不得少于 800 个非空白字符；表格和Callout不能替代解释正文。

## 13. 整篇论证地图采用固定四模块与表格型深度

- 固定使用：`2.1 全文工作模型`、`2.2 每一步为什么不能被前一步替代`、`2.3 关键箭头的证据状态`、`2.4 全文阶段导航`。不再增加重复的推进顺序、因果链或模块任务章节。
- 本节主要靠表格实现高密度导航，不套用阶段主体的长篇字数门槛。深度评价看每一格是否压缩了真实推理，而不是正文长度。
- 2.2每行必须写具体的前一步事实、仍不能区分的解释、下一方法新增的判别能力和明确证据升级；禁止“进一步验证”“继续探究”“机制不明”等空泛填充。
- 2.3只收录承重箭头。每行给出最直接证据、准确证据性质、最关键缺口以及有理由的闭合度；不得只写“相关”“部分闭合”而不说明具体依据。
- 2.4覆盖全部正式阶段。每行写真实科学问题、核心证据、证据升级、不可轻易替代的承重墙和推动下一阶段的具体缺口。
- 复杂论文中，2.2和2.3通常各不少于3个有效节点/箭头；2.4行数必须与阶段主体数量一致。简单论文不足3行时说明论文为何只有更少的承重节点。
- 表格单元格应能脱离列标题独立传达本论文信息；过短、同义重复、只写方法名或只写评价标签均视为深度不足。
